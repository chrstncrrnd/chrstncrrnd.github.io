# Introduction
Whilst building a [basic operating system](https://github.com/chrstncrrnd/c_os) as a fun project, I found myself
thinking about the following question: how much more am I gaining from understanding an operating system's implementation than
I would otherwise from simply knowing its interface.

My operating systems class at university, I suppose like all others, focused primarily on the programmer interface 
whilst diving into implementation for only a concrete subset of topics. Whilst building my OS, I did the opposite,
focusing almost exclusively on implementation, and when I had to consider it, I found the interface needed was evident.

For a while, I was mulling over how I would frame this question and develop it into an article. I came to the conclusion 
that I wanted to know when I should study either, and if there was a tangible benefit of studying one over the other.


# What's the difference
A way we can see the difference between these two things is thinking that implementation is just "a level deeper" than 
interface, however I believe this truly doesn't leave show the large discrepancy between the two.

# Why Understand Implementation
Interface is derived from implementation, in fact I would say that implementation makes interface evident. If you truly
want to understand why you interact with something the way you do, you must first understand why it is the way it is. 


# Why Build Intuition for Interface
At the end of the day, unless you're implementing one of these systems, you won't need to know the intricacies of how
they work. In fact, truly understanding a system's implementation may be only as useful as having good intuition for the
interface.
